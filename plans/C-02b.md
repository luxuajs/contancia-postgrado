# C-02b · Convertir la deriva del contrato en tareas

> Carril: contrato · Contrato: v0.1.0 · Plan escrito el 2026-11-11
> Implementa: en UNA sesión, **después de usar la app** con `CONTRATO_VALIDACION=aviso`
> (C-02a hecha). Lee solo este archivo y los archivos que nombra "Archivos".

## Objetivo
Cada discrepancia distinta registrada como `[contrato] {...}` queda como tarea en
`PROGRESO.md` (o descartada con su motivo). No se cambia código ni contrato en esta sesión.

## Archivos
- Crear: ninguno.
- Modificar: `PROGRESO.md` (raíz) — nuevas tareas en *Pendiente*; `contracts/PROGRESO.md`.
- No tocar: `contracts/openapi.yml`, `backend/`, `frontend/`.

## Contrato aplicable
No aplica (solo se leen los avisos). Formato de cada línea:
```
[contrato] {"dir":"peticion"|"respuesta","metodo":"GET","ruta":"/api/...","status":400,"errores":[{"campo":"/response/usuario/email","mensaje":"must have required property 'email'"}]}
```
`status` solo aparece en `peticion`. `ruta` es la plantilla del contrato (`/api/usuarios/{id}`)
o, si la ruta no existe en el contrato, la URL real (mensaje `not found`).

## Decisiones ya tomadas
- La v0.1.0 se extrajo del código (ADR 0001), así que la deriva es casi siempre un **error de
  extracción** → se arregla el contrato (versión de parche, 0.1.x), no el código.
- Excepción: si el contrato describe lo correcto y el código hace algo indebido (p. ej. filtra
  un campo interno), la tarea es de código.
- Las peticiones malformadas a propósito (cliente envía basura y la ruta responde 400) **no**
  son deriva: el contrato y Zod coinciden en rechazarla. Se descartan.
- Rutas `not found` fuera de `/api/` o de escáneres (`/api/.env`, `/wp-login.php`…) se descartan.

## Pasos
1. Reunir los avisos únicos (elige el que aplique):
   ```bash
   # Docker
   docker compose logs backend --no-log-prefix 2>&1 | grep '^\[contrato\]' | sort -u > /tmp/deriva.txt
   # Local: si guardaste la salida de `npm run dev` en un archivo
   grep '^\[contrato\]' <archivo-de-log> | sort -u > /tmp/deriva.txt
   wc -l /tmp/deriva.txt
   ```
   Si sale `0`, anota en `contracts/PROGRESO.md` "Sin deriva tras uso real (<fecha>)", ve al
   *Cierre* y termina.
2. Por cada línea decide, con las reglas de *Decisiones*: **contrato**, **código** o **descartar**.
   Agrupa en una sola tarea las líneas de la misma operación.
3. Añade en `PROGRESO.md` → *Pendiente*, después de C-03, una tarea por grupo, con este formato:
   ```markdown
   N. **C-1x · <operationId>: <qué no coincide>** — <contrato|código>. Aviso:
      `<dir> <metodo> <ruta>: <campo> <mensaje>`. Hecho cuando: la línea ya no aparece.
   ```
   Numera las de contrato `C-10`, `C-11`… y las de código `B-10`, `B-11`…
4. Las descartadas, en una línea cada una en `contracts/PROGRESO.md` bajo `## Deriva descartada`.

## Seguridad
- **A09 Logging** — los avisos no deben llevar datos personales (cédulas reales, correos,
  contraseñas, tokens). Si alguna línea los trae, **no copiarla** a `PROGRESO.md` y crear
  primero la tarea `B-09 · contrato.ts registra datos personales` (código).

## Skills
- Ninguna.

## Verificación
```bash
grep -c "C-1[0-9] ·\|B-1[0-9] ·" PROGRESO.md
```
Salida esperada: tantas tareas como grupos del paso 2 (0 si no hubo deriva).

## Cierre
- `PROGRESO.md` (raíz): en *Hecho* `- [x] C-02b · Deriva del contrato convertida en tareas
  (<fecha>).`; en *En curso*, la primera tarea nueva de contrato si la hay, o C-03.
- `contracts/PROGRESO.md`: quitar la viñeta de C-02b de *Lo siguiente*.
- Commit: `git commit -m "PROGRESO: deriva del contrato convertida en tareas (C-02b)" -- PROGRESO.md contracts/PROGRESO.md`

## Si algo choca con el contrato
PARAR. No cambiar el contrato ni improvisar. Escribir en *Bloqueos* qué no encaja y por qué,
hacer commit de lo hecho y terminar. El que planifica lo resuelve y actualiza el plan.
